# TESTING

Numbers below were read from the evidence files at the commit named in `validation/browser-check.json` (`commit`). If a number here disagrees with a file in `validation/`, the file wins and this page is stale.

## Commands
- `npm test` — node:test tests (the count lives in `review/gate-2/test-results.json`, which is authoritative; it is not copied here), headless (no browser, no GPU). Areas: `sim` (determinism, RNG, loop scheduling, saves, carry-over), `ai` (waking, alerts, noise, hunting, cover, actor collision, Bellhand, Retry inventory, spawn-overlap validation), `weapons`, `controls` (sprint/ADS/accuracy), `bindings`, `settings`, `automap`, `audio` (event coverage, recipes, music-stall regression), `story` (message format, sim delivery, UI queue rules on a fake clock), `tiles`, `render` (level-mesh structure built headless), `mapformat`, `save`, `route`, `campaign`, `shipped` (Marrow Quay design contracts, canonical routes, viability gates, par plausibility), and the render-truth additions: `rig-grounding` (every enemy rig x every pose x floors 0 / 0.5 / 1 / 3 m, measured on true world-space vertices, plus "a pose never writes the world root"), `enemy-hit-volume` (the sim's own hitscan aimed at the DRAWN body registers on every kind, flat and 3 m up), `sim-sector-ground` (every enemy state rides a moving floor), `debris-floor`, `pickup-toasts` (toast amounts come from `PICKUPS`), `freshness` (the evidence dependency model and bundle claims; a fixture root per case). Engine tests run on FROZEN fixtures in `tests/fixtures/` (the old hall-and-quay layout); only `shipped`/`story`/`render` read the level that ships.
- `npm run validate` / `npm run status` — manifest topology + evidence-derived status + asset file check. `npm test` no longer touches tracked evidence files (a test asserts that).
- `npm run browsercheck` — headless Chrome (SwiftShader software GL, 1280x720) against the dev server (the check count and the run time are in `validation/browser-check.json`; a few minutes), including the RENDER-TRUTH CENSUS below; writes `validation/browser-check.json` (stamped with commit, map shas and the hashes of every source set it depends on), `validation/render-ground.json`, `review/render-ground/*.png`, `validation/render-budget.json`, screenshots in `review/engine-skeleton/`. `-- --update-baseline` rewrites `validation/render-budget-baseline.json` (the reference the budget check compares against; do it deliberately).
- `npm run render-ground` — only the render-truth census (about a minute). `-- --root <dir>` runs it against another checkout (a git worktree of older code); the BEFORE evidence of PT-001 was made that way (`review/playtest/2026-10-04/`).
- `npm run verify-map -- C1E1M01` — map evidence: reachability, routes x 3 difficulties, **viability** (passive runner must not get through; perfect fighter must bleed; damage rises with difficulty; par is 2x-8x the bot's time), browser evidence bound to this map file's sha, open BLOCKERs from both known-defects files, and (Gate 2 audit repairs) the **gate-skip probe** (a fighting bot sent straight at each main exit must not finish), **ammo slack** (rounds available >= 1.5x what the perfect bot fires, every difficulty), **robustness** (a strafing fighter with 0.03 rad aim error, and one whose ammo pickups are worth 25% less, must still complete on normal), and **source hashes** (`tools/textsha.mjs`: engine, render, game shell, audio, baked assets, the map file and every route file of the map; the browser check must come from the same code, include the render-truth census and pass) so evidence made by other code goes stale.
- `npm run audio-qa`, `npm run shoot-level`, `npm run shoot-stances`, `npm run shoot-weapons` — evidence/screenshot tools; they clear the title card and overlays so the images show what a player sees.
- `npm run gate2-bundle` — assembles `review/gate-2/` (Episode 1: nine maps) from evidence, per-map table, all vantage tours, honest limits; same exit codes as gate1-bundle (3 also when the browser check did not run on a map's current file).
- `npm run build-map -- <ID>` / `npm run mapview -- <ID> [scale]` / `npm run shoot-map -- <ID> [view]` — authoring loop: compile `maps-src/<ID>.level.mjs`, top-down plan, vantage tour. `node tools/dev/dbg-route.mjs <map> <route> [difficulty] [seed]` attributes bot damage (`HITS=1` lists each hit).
- `npm run gate1-bundle` — assembles `review/gate-1/` from evidence; exits non-zero if tests fail (1), the defect list is empty (2), or evidence/code provenance differs or source is dirty (3).
- `npm run build` — production build; the dev test hook and the render diagnostics (`src/render/diagnostics.js`) must not appear in `dist/` (checked by hand: `grep -c enemyBounds dist/assets/*.js` is 0).
- Asset tools: `node tools/dev/determinism.mjs <asset>`, `node tools/dev/clean-regen.mjs`.

## What each layer proves (and what it does not)
| layer | proves | does NOT prove |
|---|---|---|
| unit/integration tests | sim rules, determinism, AI behaviours, save migrations, UI queue ordering, level structure | that anything is fun, readable or fast |
| route bot (`fights:true`) | one valid path per difficulty completes through the real input layer; a perfect fighter completes and takes real damage on every difficulty (numbers per map in `review/gate-2/maps.json`); a strafing fighter with aim error or less ammo still completes on normal | balance for humans: the bot has perfect aim |
| runner bot (`fights:false`) | a player who never shoots cannot simply walk through: dies or is blocked on every map (numbers per map in `review/gate-2/maps.json`); a fighting bot sent straight at an exit cannot finish a gated level | that the level is fair |
| **render-truth census** (`tools/dev/render-census.mjs`, inside the browser check) | every enemy of every shipped map is DRAWN where the sim stands it, measured as exact world-space vertex bounds against `groundAt(world, x, z, radius)` (the sim's own footprint contract, not the centre-cell floor): asleep (merged mesh), awake, every drawn pose forced through the real view path on the highest and lowest floor of each kind, dying, dead (flat and raised floors), on a MOVING floor going up and down; the Cantor's body, shield and ring links occupy the same space and vanish when the ring is cut; debris stops at the local floor. Tolerance: not buried by more than 0.03 m, not hovering by more than 0.30 m (reasons in `src/render/ground-contract.js`). Every enemy must be measured (exact accounting). Before the fix, against the unrepaired code in a worktree: 2 of 8 checks passed, 292 of 298 sleepers, 253 of 596 awake samples, 614 of 683 pose rows, 301 of 301 corpses and 40 of 40 moving-floor rows violated it | that the level FLOOR mesh equals the sim floor; pickups on a moving deck; silhouettes or that anything looks right; real-GPU behaviour. The hit-volume table (`hitVolume`) is measured and reported, not asserted: bodies are drawn taller than their hit cylinders |
| **hit-volume fairness** (`tests/hit-volume-fair.test.js`, `src/engine/hitvolume.js`) | the sim's hit volume matches the DRAWN enemy (owner decision 2026-10-05): hit height = drawn height within 0.10 m, a shot at the head registers and one 0.2 m over it does not, the cylinder covers 85% of the standing rig's vertices horizontally and is at most 0.15 m wider than that needs, a flare on the Cantor's head hurts it like one on its torso; the census repeats the height rule in the real game | attack poses (limbs move, the mass is the standing pose); that it feels fair |
| **outline ink on enemies** (`tests/entityflag.test.js` + a check in the browser check) | enemies and the weapon keep the ORIGINAL ink (PT-006): their materials write alpha 0, and in the real game the ink inside a Tollbearer and a Bellhand stays within 15% of the same frame drawn on the original pass (a wireframe-style version measured +90% and fails) | whether the level's corner ink reads well or is too heavy (appearance) |
| **floor and pickup truth** (`tests/render-floor-truth.test.js`) | the drawn floor is where the sim says it is: 5 samples per walkable cell of all nine maps plus both ends of every moving floor, within 2 cm (a mesh lifted 0.2 m is caught); pickups stand on the sim ground and ride a deck | water surfaces, props, appearance |

| headless Chrome check | the real game runs: real key/mouse input, un-teleported walk with ordered transmissions, prompts, F5/F9, pause layout at four window sizes, WebGL-unavailable message, Node-vs-Chrome identical state (tick count + hash) for the Gate 1 route and all ten Episode 1 routes, GPU-leak check | pointer lock, real GPU speed, how it feels |

## Failure-injection coverage
Death while holding the key (restart restores it), use/interact spam on locked and unlocked doors, exit on the same tick as fatal damage (death wins), save immediately after a transition, reload after finding a secret (no double count), a 50-level carry-over chain (bounded, no growth), corrupt/foreign/newer/old saves (v1..v7 migrate to the current v8; structurally broken saves are rejected with a reason), map changed since save, unusable storage, key placed behind its own door (reachability catches it), a body spawned inside a solid prop (validation rejects it), a music scheduler stalled for 3 minutes (no burst of catch-up notes; the test fails without the fix), WebGL unavailable (browser check), Retry after a load (unit + browser check).

## Not tested / limits (honest list)
- **Outline readability** is appearance only: `node tools/dev/shoot-outlines.mjs <dir>` makes fixed-viewpoint stills, ink masks and an ink-share number (3.4% -> 6.4% for the 2026-10-05 pass, level only; `OUTLINE=classic` runs it on the original pass; it also reports the ink inside enemy bodies); no test can say a line reads well.
- **Nobody has played Episode 1.** Every balance number (damage, ammo slack, boss pacing, par) comes from bots: a stationary perfect shot, a strafing variant, a passive runner. A bot has perfect aim on demand and no fear.
- **Pointer lock**: cannot be granted in headless Chrome or the app browser pane. The Esc -> Resume -> click flow, and whether a rejected request recovers, need a hand test in real Chrome.
- **Real-GPU performance**: only software-GL numbers exist; crowds of awake enemies are the expensive case (~830 draw calls at the M03 market and the M06 quay).
- **Audio has never been heard by a person.** Live playback was verified by engine state and log only.
- **Render truth is bounded**: it measures rigs against the SIM's ground. Nothing asserts that the drawn floor surface equals the sim's floor (the before/after screenshots show feet on the carpet in M02 and M04, which supports it), that pickups ride moving decks, or that a pose looks right.
- **Reachability** (`reach.js`) is optimistic about switches, moving floors and locks (moving floors count at either height); gating is proven by the gate-skip probe and the canonical routes, not by reachability.
- Splash damage ignores walls (audit A14, open): a flare can hurt an enemy on the far side of a wall.
- Screenshots were reviewed by eye for appearance only. The app browser pane suspends animation frames when hidden, so live verification uses headless Chrome.
- The mutation run of the Gate 2 audit was not repeated in full after the repairs; the seven surviving mutations it named now each fail a test, M12 (melee ignores height difference) is still unpinned.
