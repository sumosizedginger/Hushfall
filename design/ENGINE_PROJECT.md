# PROJECT 2: THE ENGINE (planned 2026-10-20; starts only after the game is finished and the owner has played it)

The owner (2026-10-20): "I would want to keep these" (code-posed rigs, art and sound generated by code), "this would be meant to be 100% AI controlled anyways, and not for multiplayer games, single player only", "p5 paintbrush style has been savage, and I want to see what other styles we can push for", "I would want that as our next project after this game is built, so we can build a game on top of it."

This file is the plan. Nothing in it is started. It is read by the next session after the road R17 to R27 of `design/ROADMAP.md` 0.13 is empty and the owner has played the game.

## 1. What the engine is for

A single-player engine for stylised first-person games on a deterministic grid, **operated by AI agents with a human director**: maps, rules, art and sound are written as text and code; every step has a command-line form and a machine-readable result; automated bots and audits judge the work; the human plays and decides. Procedural art, procedural sound and code-posed rigs are the identity, not a stop-gap. Not in scope: multiplayer, a GUI editor, a UI toolkit, importing art or audio files as the main path (glTF or sample import may come later as an extra), mobile, consoles.

## 2. What exists today (measured 2026-10-20)

- 46 engine modules (about 5,300 dense lines); 36 import `src/engine/defs.js` (565 lines), which mixes engine constants (`TICK`, `CELL`, `PLAYER`, `VIEW`, `DIFFICULTY`, `FX`, the mechanic tunables) with Hushfall content (`WEAPONS`, `ENEMIES`, `PICKUPS`, `PROPS`, `LOOKS`, `DROPS`, `MODS`, ...).
- `world.js` (1,360 lines) names a creature on one line; creature names appear on 34 lines in `src/engine`, 32 in `src/render`, 3 in `src/audio`, 5 in `src/game`. About 27 small modules are one mechanic or one behaviour each. About 14 map ids are hard-coded in the shell (`scenes.js`, `ending.js`, `gunlight.js`).
- The engine tests use fixtures that are copies of Hushfall maps; they cannot ship.
- Strong already: the headless deterministic sim, the map format with validator and reachability, route bots as gates, 1,300+ tests, the evidence model, the p5 bake pipeline, synthesised audio, save versioning, gamepad and rebinding, probes for performance.

## 3. The licence plan (the owner's goal: keep the assets, offer the knowledge; NOT legal advice, a lawyer reads the files before anything is published)

- Everything the owner and the agents wrote is the owner's by default. The assets (maps, painted art and the recipes that make it, sound recipes for the game's own sounds, lore and text, creature and weapon designs, the name) stay ALL RIGHTS RESERVED: no grant is made for them.
- The engine is released under MIT (Apache-2.0 is the alternative, it adds a patent grant) from a FRESH public repository whose first commit is the cleaned engine plus the sample game. The current repository is never made public: its history holds every version of every creature's stats and every map. Updates after that are exported by a script from the private source of truth.
- The name "Hushfall" is not licensed (trademark is separate from copyright); the public package gets another name.
- three.js (MIT) keeps its notice wherever it ships. A classification file lists every path as MIT or reserved; `npm run licences` fails if a path is unclassified or if the export contains a reserved path.
- Contributors: only the owner and agents, so no contributor agreement now; add one (DCO or CLA) before taking an outside pull request.
- How much of the code the owner can claim, given that agents wrote most of it, is a question for a lawyer (it depends on the country and on the amount of human direction); ask before publishing.
- Publishing is the owner's action. The builder stops at the export folder.
- Default for the 27 mechanic modules: the combat framework and the generic level mechanics (platforms, cars, belts, tide, airlocks, beams, loads, breath gates, chimes, noise tell) are engine; the named creatures and bosses, the Marksman, the Mender, the Acolyte, the signature weapons (fork, mortar, saw, loads, mods) stay private. The owner may move any of them.

## 4. The pillars (what "a true engine" means here), in order

| # | Pillar | What it is | Size |
|---|---|---|---|
| E1 | Contracts and separation | Split `defs.js` into engine constants and content tables behind a re-export shim (the 36 importers do not change; the route fingerprints, over 1,100 runs, prove nothing behaves differently); registries for rigs, atlases, sounds, looks; the shell's story parts out of the engine; a versioned API; a JSON schema for every data format (maps, defs, looks, triggers, routes) whose errors say how to fix them | L |
| E2 | The AI-operation layer (grows through every later step) | One command-line interface for every task with JSON output; a registry an agent can query for every trigger, entity and action with examples; the audit laws, the bots and the evidence model as configurable engine features; visual regression with approvals; replay bisecting; scaffold and upgrade tools | L |
| E3 | Behaviour plugins | Enemies, weapons and mechanics register as behaviours with lifecycle hooks (spawn, tick, damage, death) and deterministic randomness; stats are data; Hushfall's 27 modules become the first plugins | XL |
| E4 | THE STYLE SYSTEM (the owner's priority) | Looks as data: a stack of post passes (outline, banding, hatching, halftone, dither, palette quantising, watercolour bleed, ...) and material kits; bake backends beyond p5 (canvas, fragment shader, noise, SVG, voxel or pixel); bake only what changed; automatic atlas packing; a style lab that renders the same scenes in every style with readability metrics (contrast, silhouette overlap, the numbers already in `lumstats` and `sil-lib`) so styles can be compared by the agent and chosen by the director. The rule "all art is generated, no stock, no generative service" stays | XL |
| E5 | Animation | Keep code-posed rigs; add a procedural animation graph (state machines, blending, IK for feet and hands, spring secondary motion) | L |
| E6 | Audio | Keep synthesis; add mixer buses and ducking, reverb zones with procedural impulse responses, adaptive music from game state, loudness tools, sound captions | L |
| E7 | Physics and collision | Rays, shape casts and volume queries; simple deterministic rigid bodies; ONE maths layer (the JS engines may differ in `Math.sin` and friends, so replays could differ across browsers: node and Chrome agree today because both are V8) | L |
| E8 | World v2 (only if the second game needs it) | Named tile palettes instead of one-character tiles (the alphabet is full: Greek letters are in use), no hard cell limit (HIVE hit 25,600), stacked floors, slopes; stay grid-based, because determinism, navigation and validation depend on it | XL, risky |
| E9 | Export | A desktop wrapper; optional Steam hooks (achievements, cloud saves); quality tiers | L |
| E10 | THE PROOF | A second small game built on the engine WITHOUT editing the core. Until that works it is still Hushfall's engine | game-sized |

Order: E1, then E2 as it grows, E3, E4, E5 and E6, E7, E8 only if needed, E9, E10. The second game's concept is chosen before E3, because it decides which gaps matter.

## 5. The first steps of E1 (so the next session starts cold)

1. Split `defs.js`: `engine-defs.js` (constants, schemas, the mechanic tunables) and `content/hushfall-defs.js` (the tables); `defs.js` re-exports both. Run `route-fingerprint.mjs check`: identical.
2. Registries: creature rig by kind (`src/render/view.js`), atlas by kind, sound by event (`src/audio/events.js`), look by name, each with a Hushfall registration file.
3. Move `scenes.js`, `ending.js`, the Record's text and the cold open to a content folder; the shell asks the registry.
4. Write the sample game: three enemy kinds, three weapons, two maps, original test fixtures; the engine's own tests run on it.
5. `tools/dev/export-engine.mjs` builds the clean folder from an allowlist, runs its tests there, and fails if a reserved path is in it.
6. Any change in `src/` stales every map's real-game evidence: do E1 with the regeneration in mind (one hour of Chrome jobs, one at a time).

## 6. Acceptance for the whole project

The second game (a different style, a different set of creatures and maps) is playable, its maps pass the engine's own validator and bot gates, its art and sound are generated, and `git diff` of the engine between "Hushfall" and "game 2" is empty. The public export has a licence, a README, an architecture guide for agents and a passing test run of its own.
